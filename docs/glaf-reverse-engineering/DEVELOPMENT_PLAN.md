# GLAF 文控质检系统 — 开发计划与实施路径

本文是 `README.md` 的执行版计划，面向要「做一套类似产品」的研发与产品团队。

---

## 1. 目标定义

**目标产品**：公路工程质量管理与文控系统（合同段级可交付）  
**对标能力**：华闽通达 GLAF「工程划分 + 工序签认 + 质检表 + 文件管控 + 待办统计」  
**非目标（首期不做）**：完整无编码平台、BIM 主系统、全量计量支付、全省监管平台

**成功标准**：一个真实合同段可完成「划分 → 填表 → 签认 → 归档 → 统计」闭环，并支持施工/监理双角色。

---

## 2. 路径总览

```text
标准与模型基线
    → 基础平台（账号/权限/文件）
    → WBS 中台
    → 质检签认 MVP
    → 文控与打印归档
    → 评定与评定
    → 实施工具化 / 可选低代码
```

每阶段都应有可演示增量，避免「大爆炸」交付。

---

## 3. 阶段计划

### 阶段 0 — 标准与领域基线

**工作内容**

- 选定用表体系（交通部通用或某省地方表）
- 定义 WBS 层级：单位 / 分部 / 分项 / 工序
- 定义质检状态机：草稿 → 待审 → 退回 → 已签认 → 已归档
- 输出 Top50 施表字段字典（先路基、桥梁、隧道）

**产出**

- PRD、ER 图、状态机、表单清单、角色权限矩阵

**难度**：中（业务调研重，编码轻）

---

### 阶段 1 — 基础平台

**工作内容**

- 多租户或至少多项目隔离
- 用户 / 角色 / 组织（业主、施工标段、监理）
- 统一认证（JWT + Refresh）、操作审计
- 对象存储（附件）、基础消息/待办表

**技术建议**

- Backend: Spring Boot 3 + PostgreSQL
- Frontend: Vue3 + 组件库
- 权限：RBAC + 标段数据范围

**产出**：可登录空壳、切换项目、上传附件

**难度**：中低

---

### 阶段 2 — WBS 中台（最关键地基）

**工作内容**

- 树编辑、批量导入（Excel）、编码生成器
- 节点类型元数据（专业、是否计量、默认工序集）
- 「部位 → 应做工序/应填表」映射表
- 树查询懒加载与路径物化（`path`, `level`, `code`）

**验收**

- 1 万节点级树可流畅展开
- 能从设计清单导入并校正

**难度**：中高（数据模型一旦错，后面全返工）

---

### 阶段 3 — 质检签认 MVP（产品最小闭环）

**工作内容**

- 表单模板引擎（两层）：
  - 结构化表单（养护记录类）
  - 网格表（平整度/实测项目类）
- 任务生成：按工序批量生成待填实例
- 审批流：施工填报 → 监理签认（可退回）
- 首页待办：我的待办 / 已办 / 退回
- 基础校验：必填、数值范围、不合格高亮

**验收**

- 10 张高频表可完整跑通
- 待办数与列表口径一致

**难度**：高（表格版式 + 流程 + 权限交织）

---

### 阶段 4 — 文控能力

**工作内容**

- 文件管控目录（按 WBS / 按资料类型）
- 表单实例自动归集为电子文件
- 版本、收发、打印队列
- 元数据：题名、责任者、日期、项目代号、密级等
- PDF 导出（版式尽量贴近纸质施表）

**验收**

- 从签认完成的表单一键进入文控目录
- 支持按桩号/分项检索

**难度**：中高（版式与元数据最耗实施精力）

---

### 阶段 5 — 评定、评定与预警

**工作内容**

- 工序完成率、资料完成率、超时任务
- 分项/分部自动汇总评定（按 F80 规则子集）
- 管理层看板（合同段维度）
- 统计预聚合任务（避免 GLAF/iworks 类实时慢查询）

**验收**

- 看板秒级返回
- 评定与明细可下钻一致

**难度**：中高（规则正确性 > UI）

---

### 阶段 6 — 规模化与平台化（可选）

**工作内容**

- 模板设计器（业务人员改表）
- 规则配置（合格率公式、抽检频率）
- 项目克隆 / 标准包实施工具
- 移动端现场填报、离线暂存
- CA 签章、档案四性检测、移交包
- 与计量、试验室、BIM 的集成接口

**难度**：高到极高（从此进入平台竞争）

## 4. 团队分工建议

| 角色 | 职责 |
|------|------|
| 行业顾问/资料专家 | 用表、评定、归档规则 |
| 产品经理 | 闭环优先级、验收标准 |
| 后端 | WBS、任务、流程、统计 |
| 前端 | 树表、表单渲染、打印 |
| 表格引擎负责人 | SpreadJS/替代方案与模板 |
| 测试 | 表单计算、权限、口径一致性 |

最小团队也可 4–6 人起步，但必须有人懂公路质检资料。

---

## 5. 里程碑与依赖

```text
M1 基础平台可用
M2 WBS 导入演示
M3 质检闭环演示（对外最重要）
M4 文控检索/打印演示
M5 统计看板 + 首个试点合同段上线
M6 模板工具化，复制到第 2、第 3 个项目
```

依赖关系：

- M3 依赖 M2（没有 WBS 不要先做散表）
- M4 依赖 M3（先有业务文件，再谈文控）
- M5 依赖 M3 数据质量
- M6 依赖前序模板稳定

## 6. 工作量量级（按技术复杂度，非日历）

| 阶段 | 复杂度 | 主要工程量 |
|------|--------|------------|
| 0 基线 | 中 | 调研与标准梳理 |
| 1 基础平台 | 中低 | 常规后台 |
| 2 WBS | 中高 | 模型与导入工具 |
| 3 质检 MVP | 高 | 模板+流程+版式 |
| 4 文控 | 中高 | 元数据与 PDF |
| 5 统计评定 | 中高 | 规则与预聚合 |
| 6 平台化 | 极高 | 设计器与生态集成 |

经验判断：

- **做到 M3（可售卖试点）**：一个熟练小团队可推进的「高复杂度行业应用」
- **做到对等 GLAF 全平台**：需要长期行业积累，接近厂商级投入

## 7. 首期（MVP）范围冻结清单

**做**

- 单项目多标段
- WBS + 10~30 张核心施表
- 施工/监理签认
- 待办首页
- 附件与 PDF 打印
- 基础文件目录

**不做**

- 无编码全平台
- 全量地方表一次做完
- BIM/GIS
- 完整计量支付
- 复杂 CA（可先图片签/预留接口）

---

## 8. 质量与性能基线（吸取对标系统教训）

1. 统计与列表解耦，统计预聚合  
2. WBS 树懒加载，禁止一次下发全树  
3. 列表接口字段投影，附件分离  
4. 待办只查「待我处理」默认视图  
5. 全站 HTTPS，密码哈希，会话可吊销  
6. 从第一天打日志：`traceId`、慢查询、表单保存耗时

2. 画 WBS ER 与任务状态机

5. 实现 WBS 导入  
6. 实现 1 张结构化表 + 1 张网格表

8. 做待办首页  
9. 出 PDF 打印  
10. 用一个真实标段样例数据验收  

---

## 11. 结论

对标 GLAF 文控质检，正确路径是 **「WBS 中台 + 质检闭环 + 文控归档」三步走**，而不是先造无编码平台。  
把阶段 3 的闭环做扎实，就具备试点与打磨产品的基础；平台化能力放到阶段 6，用实施反馈驱动。
